# 08_multi_criterion_partial_evidence: Four criteria, correct code, evidence strong for two, weak for one, absent for one

## What it demonstrates

A correct `validate_password` with four criteria. Length and digit rules have strong tests, the uppercase rule has a type-only test, and the common-password rule has none.

Partial evidence must not round up. Per-criterion states are proven, proven, weak, unevidenced. Mutants M3 and M4 (delete the uppercase rule, delete the common-password rule) survive the shipped tests; the strong probes in `probes/` pass at head, confirming the code is right.

## Layout

- `intent.md` the intent source (PR description)
- `base/`, `head/` repository before and after the change
- `pr.patch` unified diff base to head (generated by `loader.py write-patches`)
- `probes/` extra tests overlaid on `head/` to show what stronger evidence would reveal (never part of the PR)
- `expected.json` labelled ground truth, validated by `../expected.schema.json`

## Ground truth

- PR correct: `true`. validate_password implements all four rules (probes pass at head), but two rules are barely or not tested.
- Expected verdict: `insufficient_evidence`. Two of four criteria are proven; C3 is weak and C4 unevidenced, so the unevidenced-intent mass exceeds uim_max. Partial evidence must not round up to verified.

## Criteria

| id | criterion | testability | expected state |
|---|---|---|---|
| C1 | a password needs at least 8 characters | testable | proven |
| C2 | a password needs at least one digit | testable | proven |
| C3 | a password needs at least one uppercase letter | testable | weak |
| C4 | a password must not be on the common-password list (case-insensitive) | testable | unevidenced |
