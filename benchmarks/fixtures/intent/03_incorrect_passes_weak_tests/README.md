# 03_incorrect_passes_weak_tests: Incorrect PR (lower bound ignored) that is green under weak tests

## What it demonstrates

An incorrect PR: `clamp` ignores the lower bound. The three new tests use `<=`, `isinstance` and `in range(...)`, so they all pass.

The central false-safety case. The strong probe `test_probe_clamp_below_returns_lo` fails at head, proving the bug is real. Mutant M1 (returning `lo` instead of `hi` for large values) also survives the shipped tests. A system that trusts the green run would wrongly verify this PR.

## Layout

- `intent.md` the intent source (PR description)
- `base/`, `head/` repository before and after the change
- `pr.patch` unified diff base to head (generated by `loader.py write-patches`)
- `probes/` extra tests overlaid on `head/` to show what stronger evidence would reveal (never part of the PR)
- `expected.json` labelled ground truth, validated by `../expected.schema.json`

## Ground truth

- PR correct: `false`. clamp never applies lo: clamp(-5, 0, 10) returns -5. A strong probe test fails at head.
- Expected verdict: `insufficient_evidence`. All linked evidence is weak, so no criterion is proven. The ground truth is an incorrect PR, so verified would be false safety; failed cannot be derived from the shipped tests alone.

## Criteria
