# 06_hallucinated_dependency: Correct, well-tested feature that declares a dependency which does not exist

## What it demonstrates

A correct, well-tested `parse_duration` whose `requirements.txt` adds `pytimeparse-ultra==3.1.4`, a package name that does not exist on PyPI. The import is guarded by `try/except ImportError`, so every test passes.

Tests cannot catch this: the evidence is strong and green. Only a dependency check (T012) can. The name was confirmed absent by requesting `https://pypi.org/pypi/pytimeparse-ultra/json` (HTTP 404) on 2026-11-02; registry state can change, so a future registry-lookup test should treat this as a recorded observation, not a permanent fact. Similar real package: `pytimeparse` (exists), which is what a typosquat check would compare against.

- `intent.md` the intent source (PR description)

## Ground truth

- PR correct: `false`. parse_duration behaves correctly, but requirements.txt pins 'pytimeparse-ultra==3.1.4'; that name returned HTTP 404 from https://pypi.org/pypi/pytimeparse-ultra/json when this fixture was authored (2026-11-02). A real install would fail or invite a typosquat.
- Expected verdict: `failed`. Evidence for both criteria is strong, but a hallucinated dependency is treated as a high-severity finding (assumed; EV-02 decides T012 severity). Without that assumption the verdict would be verified.
