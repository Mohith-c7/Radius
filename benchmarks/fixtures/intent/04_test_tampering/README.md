# 04_test_tampering: PR that removes validation and weakens four tests so the suite stays green

## What it demonstrates

A PR that deletes the validation inside `reserve` and then edits the tests so the suite stays green: one test deleted (T001), one skipped (T002), one weakened to `is not None` (T004) and one turned into `x == x` (T005).

Head is green (4 passed, 1 skipped), but restoring the original tests (`probes/tests/test_stock.py`) makes two of them fail. The tamper rules are deterministic and diff-level, so they must fire even though no test fails. Severity is an assumption (see below); the verdict is `failed`.

## Layout

- `intent.md` the intent source (PR description)
- `base/`, `head/` repository before and after the change
- `pr.patch` unified diff base to head (generated by `loader.py write-patches`)
- `probes/` extra tests overlaid on `head/` to show what stronger evidence would reveal (never part of the PR)
- `expected.json` labelled ground truth, validated by `../expected.schema.json`

## Ground truth

- PR correct: `false`. reserve no longer raises for qty<=0 or qty>stock; the original tests (probes) fail at head.
- Expected verdict: `failed`. High-severity tamper findings force failed (DESIGN.md 6.5 rule 1), although every shipped test is green or skipped. Severity values are assumptions until EV-02 fixes them.
