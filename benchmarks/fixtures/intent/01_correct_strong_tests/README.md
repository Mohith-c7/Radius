# 01_correct_strong_tests: Correct PR backed by strong, boundary-checking tests

## What it demonstrates

A correct PR that adds `apply_discount` together with tests that pin exact values at the boundaries (0, 100) and the rounding behaviour, plus tests for both error branches.

The positive control. Every criterion has strong evidence, there are no tamper findings, and the expected verdict is `verified`. A scorer that cannot return `verified` here is too conservative. The declared mutants are all caught, which is what 'strong' means in this corpus.

## Layout

- `intent.md` the intent source (PR description)
- `base/`, `head/` repository before and after the change
- `pr.patch` unified diff base to head (generated by `loader.py write-patches`)
- `expected.json` labelled ground truth, validated by `../expected.schema.json`

## Ground truth

- PR correct: `true`. apply_discount is correct; strong probes would add nothing.
- Expected verdict: `verified`. Both criteria are proven by strong, independent-of-implementation value checks and no tamper rule fires.
