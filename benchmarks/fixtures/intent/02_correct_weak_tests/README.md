# 02_correct_weak_tests: Correct PR whose tests would also pass for many wrong implementations

## What it demonstrates

A correct PR (`normalize_email`) whose tests only assert truthiness and `is not None`.

Green CI is not proof. The code is right (the strong probes in `probes/` pass at head), yet the shipped tests also pass when lowercasing, trimming and the `@` check are all removed. Expected verdict is `insufficient_evidence`, not `verified`: the right answer for the wrong reasons would be false safety.

## Layout

- `intent.md` the intent source (PR description)
- `base/`, `head/` repository before and after the change
- `pr.patch` unified diff base to head (generated by `loader.py write-patches`)
- `probes/` extra tests overlaid on `head/` to show what stronger evidence would reveal (never part of the PR)
- `expected.json` labelled ground truth, validated by `../expected.schema.json`

## Ground truth

- PR correct: `true`. normalize_email is correct (strong probes pass at head) but the shipped tests barely constrain it.
- Expected verdict: `insufficient_evidence`. The PR is correct but no criterion reaches the support threshold: C1 has only weak evidence and C2 has none, so Radius must not say verified.

## Criteria

| id | criterion | testability | expected state |
|---|---|---|---|
| C1 | normalize_email trims surrounding whitespace and lowercases the address | testable | weak |
| C2 | an address without '@' raises ValueError | testable | unevidenced |
