# benchmarks/gold: intent gold set (IN-09, EP-04)

**Status: tooling ready; annotation pending. There is no real gold data in this repository.** Everything committed here that looks like data is synthetic.

## Real versus synthetic

| Path | What it is | Committed |
|---|---|---|
| `intent/schema.json` | JSON Schema definitions for the gold files | yes |
| `intent/<pr-id>/sources.json`, `annotator-<id>.json`, `adjudicated.json` | **Real** gold data once annotation happens. Contains third-party PR text and annotator work product | **no** (git-ignored; see `.gitignore` and `DATA_HYGIENE.md`) |
| `intent/conflicts.json` | annotator conflict declarations | no |
| `samples/*.json` | sampling manifests (ids, strata, seed, power check; no text) | yes, once frozen |
| `synthetic/` | **Fake** PRs, fake annotators with planted noise, generated by `scripts/gold_synthetic.py` (seed 1), used by the tests. Every file has `"synthetic": true` and annotator ids `synth-*` | yes |
| `public/` | text-free export of the final adjudicated set (`gold_validate.py export-public`) | after owner review |

Rules that enforce the separation:

- All tools refuse synthetic data unless `--allow-synthetic` is passed; the validator rejects synthetic files in a real directory.
- Annotator ids that look like tools (`radius*`, `system*`, `llm*`, `bot*`, `extractor*`) are refused, so system output cannot be recorded as human gold.
- Numbers computed from `synthetic/` (for example agreement reports) must never be cited as results. They only show the tooling works.
- `tests/test_gold_schema.py::test_fixture_matches_generator_output` fails if the committed fixture differs from the generator.

## Layout and semantics

```
benchmarks/gold/intent/<pr-id>/        pr-id = <owner>__<repo>__pr<number>
    sources.json                       stored source texts, per-source sha256, a sources_digest
    annotator-<id>.json                one independent pass (never opened by another annotator's tool)
    adjudicated.json                   final gold for the PR (skeleton while pending)
```

- **Spans** are half-open `[start, end)` over Unicode code points (Python `str` indices; the `radius_intent` `Span` semantics) of the exact `text` stored in `sources.json`. Each explicit criterion stores the selected text, and the validator checks `text == source[start:end]`, that the span is trimmed, and that `sources_digest` matches, so any change to a source after annotation is detected.
- **Source text** is canonical: CRLF to LF, NUL and Unicode format characters removed (the class `radius_intent.normalize_text` drops); when `radius_shared` is importable at fetch time the product sanitizer (`sanitize_untrusted`) is applied first, so the text equals what the extractor sees. Casefolding and whitespace collapsing are not applied (extractors are line oriented); `normalize_text` is applied to criterion text only when matching. The sanitizer used is recorded per PR.
- `links` is reserved for LK-07 and empty now. Testability uses the five human labels of IN-05.
- Details: `docs/research/annotation/GUIDELINES.md` (what to annotate), `RUNBOOK.md` (how to run), `scripts/gold_*.py --help`.

## Tools

| Script | Purpose |
|---|---|
| `scripts/gold_sample.py` | `sample` (stratified, seeded, power check), `fetch-sources` (needs `--yes`), `queue` |
| `scripts/gold_annotate.py` | local web UI (127.0.0.1, blinded), `status`, `add`; adjudication mode with optional `--prefill-from-radius` (off by default, adjudication only) |
| `scripts/gold_agreement.py` | `compare` (IoU matching, kappa, alpha, F1, per source kind, bootstrap CIs, disagreement list), `skeleton` |
| `scripts/gold_validate.py` | `check`, `export-public` |
| `scripts/gold_pack.py` | `export` a blinded offline kit for one annotator, `import` the completed annotations (all-or-nothing validation) |
| `scripts/gold_to_eval.py` | adapter from adjudicated files to the IN-10 harness (`adapt_dev`, `adapt_test`) |
| `scripts/gold_synthetic.py` | synthetic data for tests only |

Tests: `python -m pytest tests/test_gold_*.py` (offline).
