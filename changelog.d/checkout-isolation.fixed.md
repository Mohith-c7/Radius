Each analysis now checks out into its own git worktree (removed afterwards) of a per-repository object cache that is fetched under an exclusive lock, so two analyses of one repository (two pull requests, two worker replicas) can no longer score each other's files. Every git command has a time limit (`RADIUS_GIT_CLONE_TIMEOUT_SECONDS`, `RADIUS_GIT_TIMEOUT_SECONDS`) and its process group is killed on expiry with a retryable error. The worker hourly removes stale `index.lock` files and orphaned worktrees, runs `git gc --auto`, and can delete idle repository caches (`RADIUS_GIT_CACHE_MAX_IDLE_DAYS` or `RADIUS_RETENTION_DAYS`). Worktrees live in `REPOSITORY_CACHE_DIR/.worktrees`.
