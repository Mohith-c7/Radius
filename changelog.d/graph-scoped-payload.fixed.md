`GET /analyses/{id}/graph` now returns at most `limit` nodes (default 2000, max 5000) with `truncated`, `returned_node_count` and `returned_edge_count`, and accepts `scope=impact&depth=N` for the changed files' neighbourhood; `node_count` / `edge_count` stay the full totals. The dashboard requests the impact slice, renders the analysis page without waiting for the graph, and the graph page uses the newest completed analysis instead of reporting that the API is unreachable.
