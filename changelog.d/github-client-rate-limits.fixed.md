GitHub client: honors primary (x-ratelimit-remaining/reset) and secondary (retry-after, 403/429 abuse messages) rate limits with bounded retries, jitter and a maximum total wait. Rate-limit rejections are retried even for POST; server and network errors are retried only for idempotent methods. A limit that cannot be waited out raises GitHubRateLimitError with the kind and the wait GitHub asked for.
