The v1 verdict engine no longer reports every pull request as "insufficient evidence, critical risk" for reasons unrelated to the change. A bare `&` in JSX text (`<h2>Tests & CI</h2>`) no longer makes a TSX/JSX file a parse failure (tree-sitter grammar bug). Test discovery reads the runner a file imports (`node:test` is now `node_test`, plus `vitest`, `@playwright/test`, `@jest/globals`, `mocha`), ignores helper modules that define no tests, and takes each test's `target_path` from its resolved imports (`../lib/account-model.ts`) instead of its file name. JUnit cases inherit the `file` of an enclosing `<testsuite>`. Pending CI results are reported as "Awaiting CI results for N selected test file(s)" with no score penalty and at worst medium risk; real gaps keep the high-risk cap. `affected_modules` counts the directories of affected files instead of every imported package. With Verdict v2 `off` or `shadow`, the worker republishes the v1 check run and PR comment after CI uploads results.
