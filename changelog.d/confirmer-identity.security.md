Criterion confirmations are now attributed to the authenticated principal (the signed-in user, with their GitHub login when they signed in with GitHub, or the API key) instead of an unverified header. A confirmer linked to the PR author's GitHub account never lifts the author-hint cap; one whose link is unknown is shown as `unverified confirmer`, or is refused with `RADIUS_VERDICT_V2_CONFIRM_POLICY=require_second_person`. Run the new migration (`auth_accounts.provider_login`).
