"Verify Branch" and "Run Verification" work without a pull request. An analysis can now be started for a branch or commit alone (`pullRequestId` optional, stored as null; migration `20261105_0023`); the worker diffs it against the default branch and skips GitHub publishing. An unknown `pullRequestId` answers 404 `PULL_REQUEST_NOT_FOUND` instead of a plain-text 500. The dashboard no longer invents a random pull request id, shows "Branch/commit <sha>" for such runs, turns non-JSON API errors into a readable message, uses theme colours for its inputs, offers branch and pull request pickers in the Run Verification form, filters /analyses by status and repository, and hides the GitHub App install button unless `NEXT_PUBLIC_GITHUB_APP_URL` is set.

API contract: `Analysis.pull_request_id` is now nullable in the responses of the analyses list, get, lookup, start and rerun operations (acknowledged in `docs/api/breaking-changes-ack.txt`); clients must accept null.
