Single-container hosting (`serve_with_worker`) no longer lets one large analysis take the API down: on Linux a watchdog stops the embedded worker above `RADIUS_WORKER_MAX_RSS_MB` (default 300, `0` disables), and the job is retried up to `WORKER_JOB_MAX_ATTEMPTS`, then failed with "Analysis exceeded the memory budget". The worker's peak memory on a 27k-node repository with Verdict v2 on fell from about 480 MB to about 210 MB, because the Stage A test linker no longer keeps every Python file's syntax tree and graph snapshots are written and read as plain rows instead of one ORM object per node and edge (which also lightens the API's graph endpoints).
