# Real-code mutation benchmark (self-evaluation corpus)

> Generated by `python benchmarks/real/report.py` from `benchmarks/real/results/*.jsonl`. Do not edit by hand; every number below is computed from the raw per-scenario records.

**Scope warning.** The corpus is Radius's *own* Python packages. This is a self-evaluation on a small sample (120 mutants, 16 structural scenarios, 4 subjects, one language). No external open-source repository was executed in this session. The numbers below must not be generalised to other codebases.

## 1. Research questions and hypotheses (protocol fixed before the reported run)

The methods, metrics and classification rules below were implemented in `run.py`/`metrics.py` before the reported run (an 8-mutant pilot on two subjects was used only to debug the harness and is not included).

- **RQ1 (safety).** Does Radius ever return `verified` for a change that the full suite detects? *H1: false-safe rate = 0.* Any non-zero value is a defect.
- **RQ2 (detection).** What fraction of full-suite-detected regressions does each method's selected test set detect? *H2: Radius > filename convention; full suite = 100% by construction.*
- **RQ3 (cost).** What fraction of test files does each method run, and at what wall-clock? *H3: Radius runs fewer test files than the full suite, more than the convention baseline.*
- **RQ4 (abstention).** How often does Radius abstain (`insufficient_evidence`)? No target; reported.
- **RQ5 (calibration).** Does the heuristic score separate detected from undetected changes? *H5: too little data to calibrate; the score stays a heuristic, not a probability.*

## 3. Methodology

- **Scenarios.** Per subject, `--mutants N` (file, site) pairs are sampled with `random.Random(seed)` from all mutation sites in non-test `src/**/*.py`. Operators: `flip_comparison` (e.g. `<`→`>=`, `==`→`!=`, `is`→`is not`, `in`→`not in`), `negate_condition` (`if/while c`→`not (c)`), `off_by_one` (int literal +1), `return_none` (`return e`→`return None`), `swap_add_sub` (`+`↔`-`). Each mutation is a minimal textual splice of the AST node's span; the rest of the file is byte-identical. Each scenario is one commit on its own branch; Radius gets `git diff main...HEAD`.
- **Structural scenarios** (one each per subject, targeting the source module imported by the most other modules): mutate that shared helper; delete it; rename it without updating imports; change the `package.json` manifest (benign).
- **Ground truth** (independent of Radius): full pytest suite on the scenario commit; the set of test files with a FAILED/ERROR item. Suites that fail are re-run once; a differing failing set flags the scenario as flaky. *Detected* = ≥1 failing test file. *Undetected* mutants (full suite passes) may be equivalent mutants or test-suite gaps; a `verified` verdict on them is not provably wrong and they are reported separately.
- **Radius** runs through `create_local_orchestrator()` exactly as `benchmarks/scenarios/harness.py` does: real parser + import graph, graph/convention/full-suite-fallback selection, the real `SubprocessTestRunner` executing the selected tests, and the real scorer/verdict on that outcome. Radius's run result is aggregate, so its failing *files* are attributed by re-running only the selected files (excluded from Radius wall-clock).

## 4. Baselines

- **Full suite:** all `tests/**/test_*.py`. Detects 100% of detected mutants by definition; its value is the cost reference.
- **Filename convention:** test files whose stem (minus `test_`) contains the changed module's stem (e.g. `module_resolver.py` → `test_module_resolver.py`). Selected files are executed for real. No selection ⇒ nothing runs ⇒ counts as a miss on a detected mutant.
- **Radius:** as above. Pants/Bazel-style baselines were not run (not installed; no external code allowed).

## 5. Metric definitions

Over *detected* mutants (full suite has ≥1 failing test file), per method:

- **Regression detection rate** = scenarios where ≥1 of the method's selected test files fails ÷ detected.
- **Missed-regression rate** = 1 − detection rate (selected tests all pass, error-free, or none selected).
- **False-safe verdict rate** (Radius only) = Radius verdict `verified` ÷ detected.
- **Abstention rate** (Radius only) = `insufficient_evidence` ÷ all mutants.
- **File recall** = |selected ∩ failing| ÷ |failing| (mean over detected mutants). **File precision** = |selected ∩ failing| ÷ |selected| (mean over detected mutants with ≥1 selected file).
- **Test files selected** = |selected| ÷ |all test files|, mean over all mutants (selected = executed).
- **Wall-clock** = mean seconds per scenario: full = one full pytest run; convention = pytest on its selection; Radius = whole pipeline (parse, graph, select, run, score). Subjects ran as 4 parallel processes on one machine, so absolute times include contention.
- **95% CI**: Wilson score interval.

## 8. Limitations

- **Self-evaluation bias:** the corpus is Radius's own code; its import style matches what Radius's resolver was built and tested against. Results are likely optimistic for other codebases.
- **Python only, pytest only, small N** (see §6.1 for counts; CIs are wide).
- **No external OSS executed:** cloning/executing external code was not permitted in this session; `corpus.json` lists candidates with `"executed": false` and no numbers.
- **Mutants are synthetic** (5 simple operators); real regressions can be semantic/multi-file. Undetected mutants are not split into equivalent vs test-gap (not analysed manually).
- **Packages, not whole repos:** subjects are single packages with sibling deps on PYTHONPATH; changes to those deps are not scenarios.
- **Wall-clock** measured with 4 subjects in parallel on one machine; the suites are seconds-long, so Radius's fixed analysis overhead dominates and time savings here say nothing about large suites.
- **Broad selection makes detection cheap here:** Radius selected about half of each small suite on average (§6.2), so 100% detection does not show that the graph is precise; detection on larger suites with deeper import fan-out is untested. Undetected mutants (§6.4) show the opposite risk: Radius can return `verified` where the existing tests are simply too weak, which no selection method can fix.
- **File-level ground truth:** failing *test files*, not test cases.
- Radius ran from a working tree that other agents were editing concurrently (see `Tool tree dirty`).
